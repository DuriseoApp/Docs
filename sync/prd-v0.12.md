# PRD v0.12 영향 분석

> 상태: 진행 중 (2026-11-08 사용자 승인 "start")
> 이전 버전: v0.11 → 새 버전: v0.12
> 브랜치: sync/prd-v0.12
> PR: (PR 완료 후 링크)

이 파일은 `/prd-sync` 팀원들이 읽는 계약이다. 여기 적힌 이름과 할 일을 그대로 따른다.

배경: 서버 단위 5~7과 Android 단위 5~8을 시작하기 전에 문서의 빈 곳·모순을 점검해 57건을 찾았다(점검 번호 #1~#57, 점검 결과 파일은 리드 세션의 scratchpad `scope-5to8.md`이며 이 레포에는 없다). 57건을 모두 **선택지 A(추천안)** 로 정했다. 사람이 정해야 하는 13건(#5, #8, #14, #16, #23, #27, #29, #32, #42, #45, #52, #55, #57)은 2026-11-08에 사용자가 "추천안대로"로 승인했고, 나머지 44건은 리드가 기존 규칙과의 일관성으로 정리했다. 승인 중 값이 정해진 것: #27 지연 한도 10분, #57 새 화면 ID `SCR-SET-05`.

PRD에는 제품 정책·화면 동작·문구(D-116~D-152, Q-19)와 AC·NFR·5장·8장 변경만 넣었다. 응답 필드 모양, 커서 비교, 오류 코드 사용, 인덱스 같은 구현 세부는 PRD에 넣지 않고 아래 2장·3장에만 적었다. 추천안에 없는 값·문구·이름은 정하지 않았다(5장).

진행 방식 제안: **팀** (바뀐 ID가 많고 ERD·API·SCREENS·디자인 요청서가 모두 바뀜).

## 4. 위험 항목

- [ ] DB 마이그레이션 필요: **없음.** 새 테이블·컬럼·제약·인덱스가 없다(기념일 중복 방지 `dedupe_key`·UNIQUE는 B안이라 채택하지 않음, `profileImageVersion`은 기존 `users.profile_image_key`를 노출). 단 서버 구현 변경은 있다(Server 레포 단위 5~7, 이 레포 범위 밖).
- [x] 데이터 삭제: **있음(새 자동 삭제 2가지).** ① 24시간 지난 미참조 사진 파일 정리 작업(E12, A21) ② 푸시 무효 토큰 응답 때 `devices` 행 삭제(E6, A13). 알림 30일 경계(D-141)는 조회에서 먼저 제외할 뿐 삭제 시점은 그대로다. 사용자 데이터 삭제 기준(탈퇴·해제·보관 기간)은 바뀌지 않는다.
- [ ] 권한 변경: **없음.** R- 규칙, 작성자·상대 권한 매트릭스는 그대로다(고정·해제 멱등은 권한 변경이 아님).
- [ ] 앱 호환성이 깨지는 API 변경: **없음.** 응답 필드 추가(`Memo` 정의, `totalCount`, `favoriteCount`, `profileImageVersion`)와 아직 구현되지 않은 API의 모양 확정이다. 일시 입력 형식(`...Z`만)은 서버 단위 3 구현과 같다. 푸시를 data 메시지로 통일하는 것은 Android 단위 7의 첫 구현이라 호환 문제 없음.
- [x] 개인정보 처리 변경: **있음(작음).** ① 상대 탈퇴 알림에 탈퇴 직전 닉네임이 들어가 상대의 알림 목록에 최대 30일 남는다(D-140). 탈퇴 사용자의 익명화 정책(ERD 4.3)과 어긋나 보일 수 있어 개인정보처리방침 문구 검토가 필요할 수 있다. ② 푸시 data 메시지에 알림 제목·본문이 담긴다(이미 D-46에서 잠금화면 표시를 정했고 FCM으로 보내던 내용과 같음). 새 개인정보 항목은 없고 이메일을 화면에 보이지 않게 하는 방향(D-148)이다.
- 알림 지연 한도 초과로 푸시가 생략된 알림은 알림 목록에 남는데, 그 본문의 [알림 시점] 문구("1시간 뒤" 등)는 지난 시점 기준이라 목록에서는 사실과 다를 수 있다(추천안 그대로 채택, D-137).
- 서버가 보내는 알림 본문(D-131 첫 줄, D-139 문구, D-140 이름)은 앱 화면 표기(D-129)와 별도 규칙이다. 알림 문구의 [날짜]는 D-92 그대로 연도가 없다(#42 추천안이 바꾸지 않음).
- 이 레포 밖 후속: Server PLAN 단위 5·6(메모 이벤트 발행·청취 문구), Android PLAN. 이 레포에서는 고치지 않고 PR 본문에 알린다.

## 5. 열린 질문

사용자에게 새로 물을 질문은 없다(57건 모두 결정됨). 추천안에 값이 없어 문서에 확정하지 않은 것과 확인할 것:

- **채널 ID(식별 문자열), FCM TTL**: 추천안에 없다. 채널 이름 5개만 확정했고 ID·TTL은 문서에 쓰지 않는다. Android·Server 구현에서 정할 때 필요하면 그때 PRD에 올린다.
- 해결: SYNC 모으는 시간 1초(#47), 2026-11-08 사용자 결정.
- 해결: 픽셀 수 상한 25MP(#36), 2026-11-08 사용자 결정.
- **문의 메일 주소(Q-10)**: 계속 미정이다. #55 다이얼로그와 메일은 주소 자리만 있다.
- **사진 오류 문구가 보이는 자리(#52)**: 추천안이 "공통 오류 문구" 대신 새 문구라고만 했다. 공통 오류 안내(D-88)와 같은 자리에 보이는 것으로 적었다. 다른 모양이 필요하면 디자인에서 알려 달라.
- **차이 표 35번(#16) 처리**: 추천안이 토큰 usage 예외만 적었다. SCREENS에서 D-128로 해결 처리하는 것은 리드의 판단이다(S6).
