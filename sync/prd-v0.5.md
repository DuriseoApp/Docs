## 3. 이름 확정

### 3.1 데이터 (ERD)

| 종류 | 이름 | 정의 | 관련 ID |
| --- | --- | --- | --- |
| 컬럼 변경 | users.nickname | `varchar(10)` not null | D-56 |
| 컬럼 추가 | auth_sessions.revoked_reason | `varchar(10)` null, CHECK in (`LOGOUT`, `REPLACED`, `WITHDRAWN`). `revoked_at`과 함께 기록. `REPLACED` = 다른 기기 로그인으로 끊김 | D-51 |
| 서비스 규칙 (리드 결정) | refresh 토큰 교체 | 새 세션 행을 만들지 않고 **같은 행**의 `refresh_token_hash`, `expires_at`, `last_used_at`만 바꾼다. 그래서 `sid`(= 세션 id)는 로그인부터 로그아웃까지 변하지 않고, 갱신과 동시에 나간 요청이 끊기지 않는다. 이전 refresh 토큰을 다시 보내면 해시가 없어 401 `SESSION_INVALID` | DB-02, D-51 |
| 서비스 규칙 | 로그인 (게스트 시작, 소셜 로그인. **게스트 연동은 같은 기기라 현재 세션을 그대로 쓰고 끊지 않는다** — 리드 결정) | 같은 트랜잭션에서 그 사용자의 다른 유효 세션을 모두 `revoked_at` = 지금, `revoked_reason = REPLACED`로 바꾸고, 그 사용자의 `devices` 행을 모두 지운다. 새 기기는 로그인 뒤 `PUT /me/devices`로 다시 등록한다 | D-51 |
| 서비스 규칙 | 로그아웃 | 현재 세션 `revoked_reason = LOGOUT`, 그 사용자의 `devices` 행을 모두 지운다 (한 기기 규칙이라 사용자 전체 = 그 기기) | D-50 |
| 정리 작업 | 게스트 정리 (매일 03:00 KST) | `account_type = GUEST`이고 유효한(`revoked_at IS NULL AND expires_at > now`) `auth_sessions`가 하나도 없는 사용자를 4.3 탈퇴와 같이 처리한다. 게스트는 커플이 될 수 없으므로 개인 공간만 지우면 된다. 세션 정리보다 먼저 돈다 | Q-11 |
| 테이블 변화 없음 | notifications | `COUPLE_UNLINKED` 타입을 탈퇴 해제에도 쓴다. 제목·본문만 다르다 (3.2 문구) | D-53 |

### 3.2 API

| 종류 | 이름 | 정의 | 관련 ID |
| --- | --- | --- | --- |
| 오류 코드 | SESSION_REPLACED | 401. 다른 기기 로그인으로 이 기기의 세션이 끊김. 앱은 "다른 기기에서 로그인해서 로그아웃됐어요"를 보여주고 로컬 데이터를 지운 뒤 SCR-START-01 | D-51, FR-AUTH-02.AC3 |
| 토큰 클레임 | access 토큰 `sid` | 발급한 `auth_sessions.id`. 서버는 요청마다 그 세션이 무효인지 보고, `REPLACED`면 401 `SESSION_REPLACED`, 그 밖의 무효는 401 `SESSION_INVALID` | D-51 |
| 동기화 신호 | `{"type":"SYNC","resource":"SPACE","action":"LINKED"}` | 커플 연결 커밋 뒤 두 사람의 기기 모두에 보냄. 앱은 받으면 `GET /me`로 확인하고 SCR-CAL-01 + 연결 완료 시트로 이동 | D-48, FR-COUPLE-02.AC5 |
| 앱 확인 | SCR-COUPLE-02 대기 중 5초마다 `GET /me` | 응답의 공간 종류가 COUPLE이면 이동. [연결 확인하기]도 같은 호출. 아직이면 "아직 연결되지 않았어요" | D-48 |
| 권한 규칙 | R-13 | 일정 수정에서 `isTogether` 값을 바꾸는 요청은 요청자 = `author_id`일 때만. 아니면 403 `NOT_AUTHOR` | D-52 |
| 입력 제한 | nickname | 최대 10자 (`VALIDATION_FAILED`) | D-56 |
| 검증 | Kakao | `GET https://kapi.kakao.com/v1/user/access_token_info`의 `app_id`가 설정된 둘이서 앱 ID와 같은지 확인한 뒤 사용자 ID를 쓴다. 다르면 401 `SOCIAL_TOKEN_INVALID` | NFR-SEC-01 |
| 검증 | Google | ID 토큰 서명, `iss`(accounts.google.com), `aud`(둘이서 클라이언트 ID), `exp` 확인. 실패 시 401 `SOCIAL_TOKEN_INVALID` | NFR-SEC-01 |
| 오류 코드 | SOCIAL_TOKEN_INVALID | 401. 소셜 토큰 검증 실패 (기존에 이름 없던 경우를 정함) | NFR-SEC-01 |
| 알림 문구 | 자동 기념일 | 제목 "오늘은 [기념일 이름]이에요", 본문 "함께한 지 D+[N]" | D-55 |
| 알림 문구 | 직접 기념일 | 제목 "오늘은 [기념일 이름]이에요", 본문: `repeats_yearly`이고 올해가 등록한 날짜의 해보다 뒤면 "[N]번째 맞는 날이에요" (N = 올해 − 등록 연도 + 1), 그 밖에는 "오늘이에요" | D-55 |
| 알림 문구 | 상대 탈퇴 | `COUPLE_UNLINKED`, 제목 "[상대 이름]님이 탈퇴해 연결이 해제됐어요", 본문 "함께 쓴 기록은 더 이상 볼 수 없어요" | D-53 |
