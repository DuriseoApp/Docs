# 디자인 변경 요청서: PRD v0.11

> 상태: 반영 완료 (2026-11-06, 캔버스 버전 41)
> 기준 문서: 둘이서 PRD v0.11 (`docs/PRD.md`), `docs/SCREENS.md`, `sync/prd-v0.11.md`
> 작성일: 2026-11-06

claude.ai 프로젝트 채팅에서 "디자인 반영해줘"라고 하면 `/design-sync`가 아래 내용대로 디자인 캔버스를 고치고, 이 파일의 상태를 "반영 완료"로 바꿔요.

**v0.8, v0.9, v0.10 요청서가 아직 "요청됨"이에요. 그 요청서들을 먼저(또는 함께) 반영해 주세요.**

이번 변경은 사용자가 정한 통신 중 로딩 표시예요 (PRD D-115, Q-18). **새 화면 ID는 없어요.** 공통 상태 하나를 그리는 요청 1건이고, 새 보드와 이미지는 1개예요.

---

## 디자인 변경 내용

```
PRD가 v0.11로 바뀌어서 캔버스를 수정해 줘. 기존 화면은 지우지 말고, 필요하면 "이전 버전" 줄로 옮긴 뒤 새 화면을 만들어 줘.
디자인 시스템의 토큰과 컴포넌트만 써 줘. 새 색이나 새 컴포넌트가 필요하면 만들기 전에 먼저 물어봐 줘.
화면마다 보드 이름 앞에 화면 ID를 붙여 줘.
새 보드는 기존 보드를 가져다 쓰고 그 위에 겹치는 방식으로 만들어도 돼.
항목 번호는 아래 "반영 확인" 표와 같아.

[수정]
- 없음. (기존 보드의 모양은 바꾸지 않고 새 상태 보드만 만들어.)

[새 화면]  (새 화면 ID는 없어. 공통 상태야)
1. 통신 중 로딩 표시 (보드: AddEvent.dc.html → 새 AddEventLoading) — PRD D-115, Q-18
   - 서버의 결과를 기다리는 쓰기·계정 요청 중에 보이는 공통 로딩 상태야. 예시 화면은 SCR-CAL-03 일정 작성에서 [저장]을 누른 직후로 그려 줘.
   - 화면 전체(상태바 아래부터 하단까지)를 반투명 배경으로 덮고, 가운데에 원형 로딩 표시(CircleIndicator, 계속 도는 모양)를 하나 둬.
   - 문구는 넣지 마. 덮는 동안 화면은 터치가 안 되는 상태야.
   - 배경의 색·투명도, 로딩 표시의 크기·선 두께·색은 디자인 시스템 토큰으로 정해 줘. 맞는 토큰이 없으면 새 토큰을 만들기 전에 먼저 물어봐 줘.
   - 정한 값(배경 색·투명도, 로딩 표시 크기·두께·색)을 알려 주면 `design-system.md`에 "로딩 표시" 항목으로 적어.
   - 이미지 `SCR-CAL-03--loading.png`

[삭제]
- 없음.

[확인]
2. 새 토큰·컴포넌트 필요 여부
   - 지금 디자인 시스템에 로딩 표시 컴포넌트는 없어. 새로 만들어야 하면 만들기 전에 먼저 물어봐 줘.
   - 덮는 배경은 다이얼로그·시트 뒤 막에 쓰는 기존 `scrim` 토큰을 쓸 수 있는지 먼저 봐 줘 (design-system.md "색"). 다른 값이 필요하면 먼저 물어봐 줘.
3. 보드에 있는 샘플·문구는 바꾸지 마.

다 끝나면 새로 만든 보드와 이미지, 정한 로딩 표시 값, 디자인 시스템(토큰·컴포넌트)에 바뀐 점을 정리해 줘.
```
