# 디자인 변경 요청서: PRD v0.23

> 상태: 반영 완료 (2026-11-28, 캔버스 버전 53)
> 기준 문서: 둘이서 PRD v0.23 (`docs/PRD.md` FR-AUTH-10, FR-AD-01~04, D-184~D-188, Q-24·Q-25), `docs/SCREENS.md` SCR-START-01·SCR-MEMO-01·SCR-ANNIV-01·SCR-SET-01·공통 "광고", `sync/prd-v0.23.md`
> 작성일: 2026-11-28

claude.ai 프로젝트 채팅에서 "디자인 반영해줘"라고 하면 `/design-sync`가 아래 내용대로 디자인 캔버스를 고치고, 이 파일의 상태를 "반영 완료"로 바꿔요.

이전 요청서(v0.3~v0.22)는 모두 반영 완료예요 (최신은 2026-11-25, 캔버스 버전 51, `design/change-requests/archive/prd-v0.22.md`).

이번 변경은 두 가지예요. ① 광고 세 곳(메모 목록, 기념일 목록, 전체 메뉴 배너)의 상태 이미지를 만들어요. 캔버스에 "광고 데모 (검토용 · 아직 PRD에 없음)" 줄과 보드 3개(`project/AdDemoMemo.dc.html`, `AdDemoAnniversaries.dc.html`, `AdDemoMenu.dc.html`)가 이미 있어서 그것을 정식 상태 보드로 옮겨요. ② 시작 화면에 "최근 사용" 배지와 다른 수단 확인 다이얼로그를 새로 그려요. **새 화면 ID는 없어요.** 모두 기존 화면의 상태예요.

---

## 디자인 변경 내용

```
PRD가 v0.23으로 바뀌어서 광고 자리 세 곳과 시작 화면의 "최근 사용" 배지·확인 다이얼로그를 그려야 해.
디자인 시스템의 토큰과 컴포넌트만 써 줘. 이번에는 새 토큰이 없어(광고 "광고" 배지는 `warning-50` 배경 + `warning-800` 글자, 광고 카드 배경은 `surface-50`, 모두 기존 토큰이야). 새 토큰이나 새 컴포넌트가 필요해 보이면 만들기 전에 먼저 물어봐 줘.
문구는 디자인 시스템 말투(해요체, 이모지 없음)를 따라 줘. 아래에 따옴표로 적은 문구는 그대로 써 줘. 광고주 이름·광고 제목·설명·행동 버튼의 글자는 광고가 정하므로 보드에서는 "광고 데모" 보드에 이미 있는 샘플 글자를 그대로 가져와 줘(새로 지어내지 마). 따옴표로 적지 않은 문구는 지어내지 말고 필요하면 먼저 물어봐 줘.
기존 화면은 지우지 말고, 바뀌는 화면은 원래 보드를 "이전 버전" 줄로 옮겨 줘. 항목 번호는 아래 "반영 확인" 표와 같아.

[수정]
1. SCR-MEMO-01 메모 목록 · 광고 상태 (`SCR-MEMO-01--ad.png`) — PRD FR-AD-01, D-185, Q-24, FR-AD-04
   - 캔버스의 `AdDemoMemo.dc.html`("광고 데모" 줄)을 이 상태의 정식 보드로 옮겨 줘 (이름 제안: `MemoAd.dc.html`. 다르게 정하면 canvas-map에 정한 이름으로 적어 줘).
   - 광고 카드 위치를 **일반 목록 메모 3번째 뒤에서 5번째 뒤로** 바꿔 줘. 그러려면 일반 목록에 메모가 5개 이상 보여야 해. 광고 카드 뒤에도 메모가 한 개 이상 이어지게 그려 줘(예: 메모 6개 중 5번째 뒤).
   - 광고 카드는 메모 행과 같은 폭의 한 줄 카드야. 구성: "광고" 배지(`warning-50` 배경, `warning-800` 글자) + 광고주 이름, 광고 제목, 설명 한 줄, 행동 버튼, 오른쪽 위 AdChoices 아이콘. 카드 배경은 `surface-50`.
   - 고정 영역(핀 카드)에는 광고가 없어야 해. "전체 메모 N개"와 보기 칩 개수는 광고를 세지 않은 값 그대로야.
   - 그 밖의 부분은 `SCR-MEMO-01.png`와 같아.

2. SCR-ANNIV-01 기념일 목록 · 광고 상태 (`SCR-ANNIV-01--ad.png`) — PRD FR-AD-02, FR-AD-04
   - 캔버스의 `AdDemoAnniversaries.dc.html`을 이 상태의 정식 보드로 옮겨 줘 (이름 제안: `AnniversariesAd.dc.html`).
   - 큰 광고 카드를 "다가오는 기념일" 목록 **아래**, 접힌 "지난 기념일 N개" 행 **위**에 놓아 줘. 구성: "광고" 배지 + 광고주 이름, 광고 이미지 또는 영상, 광고 제목, 설명 두 줄, 행동 버튼, AdChoices. 배지·카드 색은 위와 같아.
   - 데모 보드의 위치가 이 순서와 다르면 이 순서로 고쳐 줘.
   - 다가오는 기념일이 없는 화면(`--solo-empty`, `--no-start-date`에서 직접 기념일도 없을 때)에는 광고를 넣지 마. 그 이미지들은 바꾸지 않아.

3. SCR-SET-01 전체 메뉴 · 광고 상태 (`SCR-SET-01--ad.png`) — PRD FR-AD-03, FR-AD-04
   - 캔버스의 `AdDemoMenu.dc.html`을 이 상태의 정식 보드로 옮겨 줘 (이름 제안: `MenuAd.dc.html`).
   - 화면 아래에 적응형 고정 배너를 놓아 줘. 화면 폭에 맞추고, 시스템 내비게이션 영역 위에 놓아 줘. 메뉴 목록은 배너 위 영역에서 스크롤되는 모습으로 그려 줘.
   - 앱 정보 카드(D-170)는 목록 맨 끝에 있고 배너에 가려지지 않아야 해. 끝까지 내렸을 때 카드가 배너 바로 위에 보이는 모습으로 그려 줘(이 장면이 어렵다면 알려 줘).
   - 배너 안은 광고가 정하는 모양이야. 광고 데모의 샘플 배너를 그대로 써 줘.
   - 스낵바는 기존대로 위에서 40(D-126)이야. 이 이미지에는 스낵바를 그리지 않아도 돼.
   - 그 밖의 부분은 `SCR-SET-01.png`와 같아.

4. 광고 데모 줄 정리 — PRD v0.23
   - 위 1~3으로 세 보드를 옮긴 뒤, 캔버스의 "광고 데모 (검토용 · 아직 PRD에 없음)" 줄과 `project/AdDemoMemo.dc.html`·`AdDemoAnniversaries.dc.html`·`AdDemoMenu.dc.html` 데모 보드는 없애 줘.
   - 이 데모 줄에 PRD에 없는 광고 모양(위치, 문구)이 더 있으면 옮기지 말고 알려 줘.

[새 화면]
- 없음 (새 화면 ID 없음. 아래 5~6은 기존 화면 SCR-START-01의 새 상태야)

5. SCR-START-01 시작 · "최근 사용" 배지 (`SCR-START-01--last-used.png`) — PRD FR-AUTH-10 AC1·AC2, D-188
   - 새로 그려 줘 (이름 제안: `MainLastUsed.dc.html`). 바탕은 `Main.dc.html`과 같아.
   - 이 기기에서 카카오로 로그인한 적이 있는 모습이야. [카카오로 계속하기] 버튼에 작은 배지 "최근 사용"을 붙여 줘. [Google로 계속하기]와 [게스트로 시작하기]에는 배지가 없어.
   - 배지의 모양과 색은 기존 배지(예: 캘린더 "오늘" 배지, D-N 배지)와 같은 토큰으로 정해 줘. 버튼 안에서 위치(버튼 오른쪽 가장자리, 버튼 위 모서리 등)와 크기는 "기존 배지 모양 재사용"에서 시작해서 정하고, 새로 정한 값은 "보드 값"으로 알려 줘. 배지가 버튼의 글자("카카오로 계속하기")를 가리거나 버튼 높이를 키우지 않아야 해.
   - 새 토큰·새 컴포넌트는 만들지 마. 맞는 기존 배지가 없어 보이면 만들기 전에 먼저 물어봐 줘.

6. SCR-START-01 시작 · 다른 수단 확인 다이얼로그 (`SCR-START-01--other-method-dialog.png`) — PRD FR-AUTH-10 AC3·AC4, D-188
   - 새로 그려 줘 (이름 제안: `MainOtherMethodDialog.dc.html`). 뒤 화면은 5번의 배지가 있는 시작 화면이고 `scrim`으로 덮여 있어.
   - 카카오를 기억한 기기에서 [Google로 계속하기]를 누른 모습이야. 기존 다이얼로그(design-system "다이얼로그": 폭 최대 320, 모서리 24, 버튼 두 개 가로, 취소는 아웃라인, 확인은 채움)를 그대로 써 줘. 확인 버튼은 파괴적이지 않으므로 `brand-500` 채움이야(`danger-700` 아님).
   - 문구 (그대로):

     | 요소 | 문구 |
     | --- | --- |
     | 제목 | "이 기기에서는 카카오로 로그인했어요" |
     | 본문 | "다른 계정으로 로그인하면 새 계정이 만들어질 수 있어요. Google로 계속할까요?" |
     | 버튼 | [취소] [Google로 계속] |

   - 제목이 두 줄이 되어도 어색하지 않게 그려 줘.
   - 반대 방향(Google을 기억하고 카카오를 누름: "이 기기에서는 Google로 로그인했어요" / "… 카카오로 계속할까요?" / [취소] [카카오로 계속])은 같은 모양이라 따로 그리지 않아도 돼.

[삭제]
- 위 4의 "광고 데모" 줄과 데모 보드 3개만. 기존 화면은 지우지 마.

[확인]
7. 새 토큰·컴포넌트 필요 여부
   - 이번 변경은 새 색, 새 토큰, 새 컴포넌트 없이 기존 것만 쓰는 게 원칙이야. "광고" 배지(`warning-50`/`warning-800`), 광고 카드(`surface-50`), "최근 사용" 배지, 다이얼로그 모두 기존 토큰과 컴포넌트로 되는지 확인하고, 안 되는 게 있으면 만들기 전에 먼저 물어봐 줘.
   - `design/canvas-map.md`에 위 보드 줄을 더하고 "이전 버전"으로 옮긴 보드를 표시해 줘. 광고 카드의 크기·간격을 보드에서 새로 정했으면 "보드 값"으로 적어 줘. 필요하면 design-system 글에 "광고 카드"를 짧게 더해 줘(값만, 새 토큰 없이).

다 끝나면 바뀐 화면 ID 목록, 만든 이미지 목록, 새로 정한 보드 값, 옮기거나 없앤 보드를 정리해 줘.
```

## 화면 문서와 보드의 차이 (참고)

- 이번에는 차이가 없어요. 새 상태라 기존 보드와 비교할 것이 없고, 문구와 동작은 `docs/SCREENS.md`가 기준이에요.
- 광고 안의 글자(광고주 이름, 제목, 설명, 행동 버튼)는 광고가 정해서 이 문서에 문구가 없어요. 보드의 샘플 글자는 앱에 들어가지 않아요.
- 디자인이 나오기 전의 구현 여부는 리드가 정해요.
