# 디자인 변경 요청서: PRD v0.13

> 상태: 요청 중 (2026-11-19 작성, 캔버스 반영 전)
> 기준 문서: 둘이서 PRD v0.13 (`docs/PRD.md`), `docs/SCREENS.md`, `sync/prd-v0.13.md`
> 작성일: 2026-11-19

claude.ai 프로젝트 채팅에서 "디자인 반영해줘"라고 하면 `/design-sync`가 아래 내용대로 디자인 캔버스와 `design/design-system.md`를 고치고, 이 파일의 상태를 "반영 완료"로 바꿔요.

이전 요청서(v0.3~v0.12)는 모두 반영 완료예요 (최신은 2026-11-08, 캔버스 버전 43, `design/change-requests/archive/prd-v0.12.md`).

이번 변경은 서버 단위 1~7, Android 단위 1~8이 끝난 뒤 구현대로 문서를 맞추고(D-157, D-158) 보드 값을 글에 적은 것이에요. **새 화면 ID는 없어요.** 새 보드도 없고, 캔버스는 보드 두 곳(Menu, Calendar)의 작은 수정이에요. 요청은 4건이에요. 앱 아이콘과 알림 작은 아이콘(Q-20)은 이번 요청서에 넣지 않아요.

보드 값과 문구는 지금 캔버스(버전 43)가 맞아요. 이번에 바뀐 문구와 규칙은 `docs/SCREENS.md`에 적었고, 아래에 적은 곳만 고쳐요.

---

## 디자인 변경 내용

```
PRD가 v0.13으로 바뀌어서 캔버스와 디자인 시스템 글을 수정해 줘. 기존 화면은 지우지 말고, 고치는 보드는 이전 모양을 "이전 버전" 줄로 옮긴 뒤 새로 만들어 줘.
디자인 시스템의 토큰과 컴포넌트만 써 줘. 새 색이나 새 컴포넌트가 필요하면 만들기 전에 먼저 물어봐 줘.
문구는 디자인 시스템 말투(해요체, 결과가 보이는 동사, 이모지 없음)를 따라 줘. 아래에 따옴표로 적은 문구는 그대로 써 줘. 따옴표로 적지 않은 문구는 새로 지어내지 말고 필요하면 먼저 물어봐 줘.
항목 번호는 아래 "반영 확인" 표와 같아. [수정]이 1~3번, [확인]이 5번, [대기]가 4번이야.

[수정]
1. SCR-SET-01 앱 정보 카드: 새 버전이 있을 때의 버튼 문구 (보드: Menu.dc.html 172행) — PRD FR-SET-02 AC4, D-158
   - 버튼 "새 버전 1.1.0 업데이트"를 "업데이트"로 바꿔 줘. 새 버전 이름은 보이지 않아. Play 인앱 업데이트가 새 버전 이름을 주지 않기 때문이야.
   - 카드의 다른 문구와 상태(확인 중, 확인할 수 없음)는 그대로 둬.
   - 버튼이 보이는 `SCR-SET-01*.png`만 다시 만들어 줘 (카드가 보이는 이미지 중 새 버전 상태).

2. SCR-CAL-01 날짜 목록의 메모 카드: 본문 한 줄 빼기 (보드: Calendar.dc.html 메모 카드, 샘플 `memo` 필드를 보여 주는 줄) — PRD D-157
   - 메모 카드는 "메모" 표시와 제목 한 줄만 보여 줘. 본문(샘플의 "세 곳 골라놨는데 …", "충전기, 여권 사본, 접이식 우산" 등) 줄을 빼 줘.
   - 일정 카드의 일정 메모 줄은 그대로 둬. 메모 카드만 해당해.
   - 펼친 달력(`SCR-CAL-01--expanded.png`)에 메모 막대가 있다면 빼 줘. 일정·기념일 막대는 그대로야.
   - 달라지는 `SCR-CAL-01*.png`만 다시 만들어 줘. 바뀌는 곳이 없으면 "그림 변경 없음"이라고 알려 줘.

3. 디자인 시스템 글(`design/design-system.md`)에 보드 값 맞추기 — PRD D-157, `docs/SCREENS.md` "보드 값"
   - "초대코드 입력 오류 줄 (SCR-COUPLE-03)" 표의 위치 행: "코드 칸 아래 4 (칸과 아래 요소 사이 gap 12에서 위 여백 -4)"를 "코드 칸 아래 8"로 고쳐 줘. 보드(`InviteEnter.dc.html` 38행)는 간격 12에서 위 여백 -4를 빼서 실제로 8이고, 그림도 8이야. 글만 틀렸어. 보드와 이미지는 그대로 둬.
   - SCR-CAL-02 일정 제목 값을 적어 줘: 24 / 행간 1.35 / 700, 자간 -0.01em (`EventDetail.dc.html` 28행). **새 토큰을 만들지 말고** `headline`(26/35/700)·`title-lg` 같은 기존 토큰과 다르다고 "보드 값"으로 적어 줘 (소개 문구 17/400처럼 화면 값으로 적는 방식).
   - 메일 다이얼로그 "주소 상자" 설명(310행 근처)의 "주소는 PRD Q-10이 정해지지 않아 `[문의 메일 주소]`"를 "주소는 D-155 `jucoding99@gmail.com`, 이미지는 자리표시"로 고쳐 줘.
   - 보드와 이미지는 바꾸지 마.

[대기]
4. 앱 아이콘과 상태바 알림 작은 아이콘 — PRD Q-20 대기
   - 모양이 정해지지 않았어(출시 전 필수, 기본값 없음). Q-20이 정해지면 따로 요청서를 만들어. 이번에는 아무것도 그리지 마. `AppIcons.dc.html`도 그대로 둬.

[삭제]
- 없음.

[확인]
5. 새 토큰·컴포넌트 필요 여부
   - 이번 변경은 새 색, 새 토큰, 새 컴포넌트 없이 기존 것만 쓰는 게 원칙이야. 1~3번에서 필요해 보이는 게 있으면 만들기 전에 먼저 물어봐 줘.
   - 보드에 있는 샘플·문구는 위에 적은 곳 말고는 바꾸지 마.

다 끝나면 바뀐 화면 ID 목록, 다시 만든 이미지 목록, 2번에서 그림이 바뀌었는지, 디자인 시스템 글에 바뀐 점을 정리해 줘.
```
