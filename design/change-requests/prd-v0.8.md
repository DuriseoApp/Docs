# 디자인 변경 요청서: PRD v0.8

> 상태: 요청됨
> 기준 문서: 둘이서 PRD v0.8 (`docs/PRD.md`), `docs/SCREENS.md`, `sync/prd-v0.8.md`
> 작성일: 2026-10-27

claude.ai 프로젝트 채팅에서 "디자인 반영해줘"라고 하면 `/design-sync`가 아래 내용대로 디자인 캔버스를 고치고, 이 파일의 상태를 "반영 완료"로 바꿔요.

이번 변경은 서버 단위 2(커플)와 Android 단위 2(인증) 범위 점검에서 나온 빈 곳을 사용자가 정한 결과예요 (PRD D-83~D-88, Q-12). 화면에 보이는 새 모양은 없어요. **캔버스 수정은 게스트 ID 샘플 값 하나**이고, 나머지는 화면 이미지만 다시 만들어요. 새 화면, 새 토큰, 새 컴포넌트는 없어요.

보드 값과 문구는 지금 캔버스(버전 38)가 맞아요. 바뀐 문구와 규칙(공통 오류, 가입일 형식, 로그아웃·탈퇴 실패, 처음 만난 날 지우기 없음 등)은 `docs/SCREENS.md`에만 적고 보드는 고치지 않아요.

---

## 디자인 변경 내용

```
PRD가 v0.8로 바뀌어서 캔버스를 조금 수정해 줘. 기존 화면은 지우지 말고 "이전 버전" 줄로 옮긴 뒤 새 화면을 만들어 줘.
디자인 시스템의 토큰과 컴포넌트만 써 줘. 새 색이나 새 컴포넌트가 필요하면 만들기 전에 먼저 물어봐 줘.
화면마다 보드 이름 앞에 화면 ID를 붙여 줘 (예: "SCR-SET-01 계정 · 게스트").
문구는 디자인 시스템 말투(해요체, 결과가 보이는 동사, 이모지 없음)를 따라 줘. 아래에 따옴표로 적은 문구는 그대로 써 줘.
[게스트 ID], [닉네임] 같은 대괄호는 자리표시야. 1번만 샘플 값으로 바꾸고 나머지는 그대로 둬.

[수정]
1. SCR-SET-01 계정 · 게스트 (보드: Account.dc.html) — PRD Q-12, FR-SET-01
   - 게스트 ID 값 자리의 "[게스트 ID]"를 샘플 UUID 36자로 바꿔 줘. 예: 0192f3a1-7c2e-7b8d-9a41-3f5e6d7c8b9a
   - 이 값이 한 줄에 들어가는지, 줄바꿈이 되는지 확인해서 어떻게 보이는지 알려 줘. 줄이거나 가운데를 생략하지 말고 36자를 모두 보여 줘 (PRD Q-12: 줄이지 않고 그대로 보여줘요).
   - 라벨 "게스트 ID", 글자 크기·굵기·색, 위치, 나머지 요소(안내 배너, 소셜 로그인 버튼, 안내 문구, [탈퇴하기])는 바꾸지 마.
   - 이 보드는 AccountWithdraw, AccountMember, AccountGuestExisting, AccountGuestExistingConfirm이 가져다 쓰고 있어서, 고치기 전 보드를 "이전 버전" 줄로 옮기면 그 보드들의 연결이 끊어질 수 있어. 그러면 그 자리에서 고치고 이전 모습은 캔버스 버전 기록에 남겨 줘. 어떻게 했는지 알려 줘.
   - 이미지 `SCR-SET-01--account-guest.png`를 다시 만들어 줘.
   - 같은 보드를 게스트 상태로 가져다 쓰는 AccountGuestExisting, AccountGuestExistingConfirm도 뒤 화면에 게스트 ID가 보여서, 이미지 `SCR-SET-01--account-guest-existing.png`, `SCR-SET-01--account-guest-existing-confirm.png`를 같이 다시 만들어 줘 (보드 수정은 없어).

[확인]
2. SCR-SET-01 탈퇴 확인 (보드: AccountWithdraw.dc.html) — PRD FR-AUTH-06
   - 보드는 이미 뒤 화면 맨 아래 버튼과 다이얼로그 확인 버튼이 모두 "탈퇴하기"야. 캔버스는 고치지 마.
   - 지금 이미지 `SCR-SET-01--withdraw-dialog.png`는 뒤 화면 맨 아래 버튼이 "회원 탈퇴"로 보여서 보드와 달라. 캔버스 수정 없이 이미지만 다시 만들어 줘. 다시 만든 이미지에서 "탈퇴하기"로 나오는지 알려 줘.
   - 만약 보드에도 "회원 탈퇴"가 남아 있으면 고치지 말고 알려 줘.

[새 화면]
- 없음

[삭제]
- 없음

3. 새 토큰·컴포넌트 필요 여부
   - 이번 변경은 새 색, 새 토큰, 새 컴포넌트 없이 샘플 값만 바꾸는 것이 원칙이야.
   - 36자 샘플 UUID 때문에 새 토큰이나 컴포넌트가 필요해 보이면 만들기 전에 먼저 물어봐 줘.

다 끝나면 바뀐 화면 ID 목록, 다시 만든 이미지 목록, 1번의 줄바꿈 모양, 2번의 "탈퇴하기" 확인 결과, 디자인 시스템(토큰·컴포넌트)에 바뀐 점이 있는지 정리해 줘.
```

## 이미지 이름

화면 ID + `--<상태>`로 만들어요. 새 이미지는 없고, 아래 기존 이미지를 다시 만들어요.

| 보드 | 이미지 | 이유 |
| --- | --- | --- |
| Account (게스트) | `SCR-SET-01--account-guest.png` | 게스트 ID 샘플 값 (캔버스 수정) |
| AccountGuestExisting | `SCR-SET-01--account-guest-existing.png` | 뒤 화면의 게스트 ID가 바뀜 (보드 수정 없음) |
| AccountGuestExistingConfirm | `SCR-SET-01--account-guest-existing-confirm.png` | 뒤 화면의 게스트 ID가 바뀜 (보드 수정 없음) |
| AccountWithdraw | `SCR-SET-01--withdraw-dialog.png` | 이미지의 "회원 탈퇴"를 보드의 "탈퇴하기"로 맞춤 (캔버스 수정 없음) |
