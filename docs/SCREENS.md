이 문서는 PRD 5장 화면 목록의 화면별 명세예요. Android·iOS 에이전트는 화면을 만들 때 이 문서를 기준으로 하고, 이미지(`design/screens/<화면 ID>.png`)는 레이아웃 확인용으로 써요. 값과 문구가 이미지와 다르면 이 문서가 우선이에요. PRD와 충돌하면 PRD가 우선이에요.

**표기**
- `디자인: 반영됨`은 이미지가 있고 이 문서와 맞다는 뜻이에요.
- `디자인: 변경 요청됨 (PRD vX.Y)`는 디자인 변경 요청서로 수정을 요청했고 아직 캔버스에 반영되지 않았다는 뜻이에요. 기존 이미지는 레이아웃 참고용으로만 쓰고, 바뀐 부분은 이 문서를 따라요. 이미지가 없는 새 화면은 디자인이 나오기 전까지 구현하지 않아요. `이미지 예정 <이름>`은 요청서대로 새로 그릴 이미지의 이름이에요 (아직 `design/screens/`에 없어요). 지금은 `이미지 예정`이 남아 있는 곳이 없어요.
- `차이:`는 디자인이 PRD와 다른 점이에요. **구현은 PRD를 따르고**, 차이는 사람이 정리할 때까지 그대로 둬요. PRD v0.4에서 대부분 해결됐어요. 전체 목록은 맨 아래 "PRD와의 차이"에 있어요.
- `디자인: 반영됨`이어도 이 문서에 PRD v0.5·v0.6·v0.8·v0.9에서 바뀐 동작이 적혀 있으면 그 동작은 이 문서를 따라요 (이미지에 없는 동작은 "디자인 없음"이나 "이미지 예정"으로 표시해요).
- 샘플 이름·숫자(`[상대 이름]`, `D+189` 등)는 자리표시예요. 실제 값으로 바꿔요.
- PRD에 있는 ID만 써요. 상태별 화면과 다이얼로그는 `SCR-…--<상태>.png`로 구분해요.
- 체크리스트, 메모 검색, 메모 읽음·NEW 표시, 우리 색상의 직접 색 고르기는 범위 밖이에요 (D-19, D-41). 화면에 넣지 않아요.

- **진입**: 첫 실행, 로그아웃 후, 탈퇴 후, 다른 기기 로그인으로 로그아웃됐을 때, SCR-COUPLE-01의 "다른 계정으로 로그인"(회원)으로 로그아웃한 뒤 (D-80)
- **구성**: 로고(겹친 두 원), 앱 이름 "둘이서"(display), 소개 "일정도, 공지도, 메모도 / 우리 둘만 보는 공간에.", 기능 칩 3개, "간편하게 시작하기" → [Google로 계속하기](채움) [카카오로 계속하기](아웃라인), "또는" 구분선, [게스트로 시작하기](면 버튼), 게스트 설명, 동의 문구(이용약관·개인정보처리방침 링크)
- **로고 파일과 접근성**: 로고는 `design/logo/duriseo-mark-start.svg`예요 (112×72). 접근성 문구는 "두 원이 겹친 둘이서 로고"예요 (`Main.dc.html` 20행).
- **문구**
  - 기능 칩 "쉐어 캘린더", "공지사항", "메모장" (`Main.dc.html` 31~33행)
  - 게스트 설명 "로그인 없이 바로 써볼 수 있어요. 나중에 메뉴 › 계정에서 로그인하면 지금까지의 기록이 그대로 옮겨져요."
  - 동의 문구 "시작하면 만 14세 이상이며, 이용약관과 개인정보처리방침에 동의하는 것으로 봐요." 나이는 따로 묻지 않아요. 두 링크는 웹 페이지를 열어요 (D-63, FR-AUTH-08).
- **동작**: 게스트 → SCR-CAL-01. 신규 소셜 회원 → SCR-COUPLE-01. 기존 회원 → 그 계정의 현재 상태

### SCR-COUPLE-04 연결 완료 시트

- **관련 FR**: FR-COUPLE-02, FR-COUPLE-03, FR-COUPLE-04, FR-COUPLE-06
- **진입**: 연결 직후 SCR-CAL-01 위에 하단 시트로 떠요 (두 사람 모두). 전체 화면이 아니에요 (D-49). 앱이 꺼져 있었거나 시트에서 고르지 않고 앱을 껐으면 다음 실행 때 SCR-CAL-01 위에 다시 떠요.
- **구성**: 제목 "[상대 이름]님과 연결됐어요", "처음 만난 날" 날짜 선택("날짜를 골라 주세요", 안내 "D-day와 기념일이 이 날을 1일로 계산돼요. 둘 중 누구든 나중에 바꿀 수 있어요.") + [나중에 하기], "혼자 쓴 기록" — 개수 안내("일정 [N]개, 기념일 [N]개, 메모 [N]개가 있어요.")와 [가져오기] / [가져오지 않기] 선택 카드, "내 기록만 정해요. 상대의 기록은 상대가 정해요.", [시작하기]
- **처음 만난 날**: 건너뛸 수 있어요. [나중에 하기]를 누르거나 고르지 않고 시작하면 SCR-CAL-01 D-day 자리에 처음 만난 날 입력 안내가 보여요. 고를 수 있는 날짜는 1950-01-01 ~ 오늘이에요. 오늘보다 뒤의 날짜와 1950-01-01보다 앞의 날짜는 고를 수 없어요 (FR-COUPLE-04 AC2·AC3, D-74). 둘 중 누구든 나중에 설정에서 바꿀 수 있어요.
- **처음 만난 날 칸 (D-98)**: 칸을 누르면 처음 만난 날 선택 시트가 이 시트 위에 한 겹 더 떠요. 그 시트의 [저장]은 칸에 날짜를 채우기만 하고 서버를 부르지 않아요. 서버에는 [시작하기]를 누를 때 저장해요([시작하기] 순서는 아래 "동작"). [나중에 하기]는 고른 날짜를 비워요. 처음 만난 날이 이미 있는 공간(상대가 먼저 정했거나 복구된 공간, `MeSpace.startDate`)이면 칸에 그 날짜를 보여주고 [나중에 하기]는 숨겨요 (FR-COUPLE-04 AC4). 그림은 칸에 "2026년 3월 14일"(샘플)이 `ink-900` 글자로 보이고, 혼자 쓴 기록 영역(개수 안내, [가져오기]·[가져오지 않기])은 그대로예요 — `SCR-COUPLE-04--date-set.png`
- **지우기 없음**: 고른 날짜를 지우는 버튼은 없어요. 다른 날로 바꿀 수만 있어요 (D-84).
- **개수 (D-93)**: 개수 안내의 [N]은 서버가 알려 주는 혼자 쓴 기록 개수(`MeSpace.importCounts`의 `events`, `anniversaries`, `memos`)예요. 기념일은 직접 기념일만 세요. 0개인 종류도 보여줘요 (Q-13 기본값, 예 "일정 3개, 기념일 0개, 메모 2개가 있어요."). 문구는 보드 `Calendar.dc.html` 160행 그대로예요 (FR-COUPLE-03 AC1).
- **혼자 쓴 기록**: 혼자 쓴 기록이 있으면 시트를 처음 열면 [가져오기]가 미리 선택돼 있어요 (FR-COUPLE-03 AC5, D-76). [가져오기]와 [가져오지 않기] 중 하나로 [시작하기]를 누르기 전에는 시트를 닫을 수 없어요. 밀어서 닫기, 뒤로 가기도 막아요 (FR-COUPLE-03 AC4). [가져오지 않기]로 시작하면 확인 다이얼로그가 떠요.
- **상태**
  - 혼자 쓴 기록이 있음: 위 구성 그대로 (`SCR-COUPLE-04.png`)
  - 혼자 쓴 기록이 없음: 기록 영역(제목, 개수 안내, 선택 카드, "내 기록만 정해요…" 안내)이 없고 시트를 닫을 수 있어요 — `SCR-COUPLE-04--no-records.png`
  - 처음 만난 날이 이미 있음: 칸에 날짜가 보이고 [나중에 하기]가 없어요 — `SCR-COUPLE-04--date-set.png`
  - 유예 기간 안 재연결(복구, `restored: true`): 이전 공간이 복구되고 해제 후 새로 쓴 기록만 고름. 같은 시트와 같은 문구를 써요 (FR-COUPLE-06 AC2)
  - 가져오기를 정하기 전에 연결이 해제되면: 혼자 쓴 기록은 원래 개인 공간으로 그대로 돌아가요 (FR-COUPLE-05 AC4, D-78)
  - 요청 중: 공통 표의 "요청 중" 규칙대로 원형 로딩 표시가 화면을 덮어요 (D-115)
- **다시 뜨는 조건 (D-98)**: 혼자 쓴 기록이 없어도 시트를 닫기 전에 앱을 끄면 다음 실행 때 다시 떠요. 시트를 닫거나 [시작하기]를 누른 뒤에는 그 연결에 대해 다시 뜨지 않아요 (FR-COUPLE-03 AC6).
- **동작**: [시작하기]를 누르면 아래 순서로 처리하고, 끝나면 시트가 닫히고 SCR-CAL-01이 그대로 보여요. 고른 처음 만난 날은 D-day와 자동 기념일에 바로 반영돼요.
  1. 처음 만난 날을 골랐으면 서버에 저장해요.
  2. 기록 선택이 있으면 가져오기 또는 삭제를 서버에 알려요(되돌릴 수 없는 삭제를 마지막에 해요).
  3. 시트를 닫고, 이 연결에 대해 확인했다고 기기에 기록해요.
  중간에 실패하면 거기서 멈추고 공통 오류(공통 표)를 보여줘요. 시트는 그대로 있고, 다시 누르면 처음부터 해요. 이미 정해진 상태(`NO_IMPORT_PENDING`)면 정한 것으로 보고 3번으로 가요 (FR-COUPLE-04 AC4, D-98).
- **다이얼로그**: "가져오지 않기"로 시작하면 "혼자 쓴 기록을 삭제할까요?" / "가져오지 않으면 혼자 쓴 일정 [N]개, 기념일 [N]개, 메모 [N]개가 삭제되고 되돌릴 수 없어요."(보드 `Calendar.dc.html` 176행) [취소] [삭제하고 시작]. [N]은 시트의 개수 안내와 같은 값이에요 (FR-COUPLE-03 AC2, D-93) — `SCR-COUPLE-04--drop-dialog.png`
- **보드 문구** (`Calendar.dc.html`): 카드 부제 "함께 쓰는 캘린더와 메모로 옮겨요"([가져오기], 163행), "혼자 쓴 기록은 삭제돼요"([가져오지 않기], 164행). 접근성 문구 "혼자 쓴 기록 가져오기"(선택 묶음, 162행), "닫기"(기록 없음 상태의 닫기 버튼, 142행).
- **디자인**: 반영됨 (2026-11-06, 캔버스 버전 41, PRD v0.9) — 처음 만난 날 칸에 날짜가 들어간 상태 `SCR-COUPLE-04--date-set.png`를 새로 그렸어요. 개수 문구, 처음 만난 날 칸 동작, 다시 뜨는 조건은 이 문서를 따라요. 이전 반영분: 반영됨 (2026-10-22, 캔버스 버전 38) — `SCR-COUPLE-04--no-records.png`(기록 영역 없음, 제목 오른쪽에 닫기 버튼). 기존 시트와 다이얼로그 이미지는 그대로이고, [가져오기] 미리 선택은 v0.5 디자인대로 확정됐어요(D-76). 이전 반영분 (2026-10-22, 캔버스 버전 35, design/screens/SCR-COUPLE-04.png, SCR-COUPLE-04--drop-dialog.png) — 캘린더 위 하단 시트(위 모서리 24, 손잡이, 닫기 버튼 없음). 뒤의 캘린더 앱바는 "처음 만난 날 입력하기 ›". 이전 전체 화면 보드(Connected·ConnectedDialog)는 "(v0.4)"로 남겨 뒀어요.
